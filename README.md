# Основы права

Готовая статическая викторина для двух участников. Без backend, установки зависимостей и внешних ресурсов во время игры. Изображение и шрифты находятся в `assets`.

## Локальный запуск

Нужен Node.js 22 или новее. Откройте терминал в папке проекта и выполните:

```sh
npm start
```

Откройте http://127.0.0.1:4173. Остановка сервера — Ctrl+C. Можно использовать любой другой статический HTTP-сервер. Простое открытие `index.html` через `file://` не поддерживается: браузер ограничивает загрузку ES-модулей и JSON.

## Банк вопросов и два режима

`questions.json` содержит предоставленный пользователем банк без изменений: **100 вопросов**, из них 75 с вариантами и 25 устных. Участники: Кадырбекова Еркеназ (`erkenaz`) и Торгаутова Алсу (`alsu`). Банки `questionSets.forErkenaz` и `questionSets.forAlsu` содержат по 50 вопросов. Демо отключено; `demoQuestions.js` не включается в опубликованную сборку.

### choice

Четыре варианта `options` отображаются как A/B/C/D. `correctIndex` — индекс от 0 до 3, он обязан указывать на значение `correctAnswer`. Если индекс уже есть, варианты **не перемешиваются** ни при новом старте, ни при обновлении. Старый формат без индекса поддерживается: в нём сравнение идёт по `correctAnswer`, а порядок вариантов перемешивается при старте.

### oral

Вариантов A/B/C/D нет; `options` — пустой массив или отсутствует. Сначала видны вопрос, метка «УСТНЫЙ ВОПРОС» и кнопка «Показать ответ». До раскрытия `correctAnswer` не вставляется в игровой экран. После раскрытия видны эталон и кнопки «Верно +1» / «Неверно». Проверяющий участник оценивает ответ вслух: отвечающему начисляется 1 или 0 баллов. Только после оценки доступен следующий ход.

Само раскрытие не добавляет баллы. Оценить до раскрытия, повторно начислить балл или изменить уже принятую оценку нельзя. Раскрытие и оценка сохраняются независимо: обновление страницы между ними не теряет этап.

В работе над ошибками для устных вопросов показываются вопрос, отметка «Проверяющий не засчитал устный ответ» и эталон. Текст произнесённого ответа не записывается и не выдумывается.

### Изменение данных

- `id` вопроса уникален. `number` идёт от 1 по порядку внутри массива.
- `reader` и `respondent` ссылаются на `players[].id`; у вопроса всегда разные читающий и отвечающий.
- Ключ банка образуется как `for` + id участника с заглавной первой буквой: `erkenaz` → `forErkenaz`. Старые `player1` / `forPlayer1` также поддерживаются.
- `section` и/или `category` — строки; `category` имеет приоритет в UI.
- Вопросы, варианты и правильные ответы берутся из JSON. Валидатор проверяет режим, роли, номера, уникальность вариантов и согласованность индекса с ответом.
- Если оба банка пусты, включается отдельное демо. Один пустой или некорректный банк вызывает понятную ошибку.
- После изменения данных для локального сайта достаточно обновить страницу. Для опубликованной версии нужно собрать и опубликовать обновление.

## Имена

Имя второго участника меняется **в одном месте**: значение `players[1].name` в `questions.json`. Имя первого — `players[0].name`. Все игровые экраны, правила, результаты и фильтры используют эти значения. Не дублируйте изменения в HTML: начальное содержимое заменяется данными банка.

## Механика и сохранение

Новая попытка начинается с трёхсекундной заставки «3–2–1»: круговой индикатор показывает ход секунды, подписи напоминают роли участников, после чего первый вопрос открывается автоматически. При продолжении сохранённой попытки заставка не повторяется.

Первый ход: Еркеназ читает вопрос Алсу. Второй ход: Алсу читает вопрос Еркеназ. Далее роли чередуются. Верный ответ приносит 1 балл отвечающему; неверный — 0. Повторное нажатие баллы не начисляет. Следующий вопрос открывается только после отдельного нажатия. В режиме choice клавиши 1–4 выбирают ответ; Tab/Enter работают на всех кнопках.

Состояние автоматически сохраняется в `localStorage`, ключ `osnovy-prava.quiz.v1`: ход, ответы, ошибки, порядок вариантов, раскрытые устные ответы, ручные оценки, счёт, прогресс и активный участник. Внутренняя версия сохранения — 2; старый демо-прогресс не переносится в новый банк. При открытии доступно продолжение или сброс с подтверждением. Обновление после выбора ответа не теряет результат и не начисляет балл повторно. Состояние синхронизируется между вкладками одного браузера.

Сохранение привязано к этому браузеру и адресу сайта. Локальная и опубликованная версии имеют отдельный прогресс. Изменение банка или имён открывает новую попытку, чтобы старые ответы не смешивались с новыми вопросами. При запрете хранилища игра продолжает работать с предупреждением.

После завершения: отдельные результаты, проценты, победитель или ничья и работа над ошибками с фильтрами. Если ошибок нет, показывается соответствующий экран.

## Файлы и проверки

`app.js` — экраны и события; `engine.js` — валидация и игровая логика; `styles.css` — обложка и общие стили; `game.css` — игра, результаты, адаптив; `oral.css` — устный режим; `demoQuestions.js` — только временные данные.

```sh
npm test
npm run build
```

Проверки логики включают чередование, защиту от двойного ответа, восстановление, повреждённые сохранения, подсчёт результатов и полный проход всех 100 реальных вопросов с обоими режимами. Дополнительно проверяются восстановление до и после оценки, запрет преждевременной оценки, неизменность индексированных вариантов и отсутствие повторных баллов. Тестовые объекты не добавляются в рабочий банк. `build` проверяет JavaScript и JSON и копирует готовые статические файлы в `dist`. Для локального запуска сборка не нужна. При публикации после изменения JSON выполните сборку и загрузите содержимое `dist` на статический хостинг.

В поддерживающих WebMCP браузерах доступен необязательный инструмент `get_quiz_progress` только для чтения. Обычный интерфейс от него не зависит.
